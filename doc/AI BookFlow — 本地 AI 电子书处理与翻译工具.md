# AI BookFlow — 本地 AI 电子书处理与翻译工具  
**项目版本：** V1.0 MVP 技术实施规格 **目标平台：** macOS Apple Silicon（Mac mini M4，24GB 统一内存） **推理平台：** Ollama，本地运行 **主要使用场景：** 个人电子书整理、外文翻译及 Kindle Oasis 阅读 **核心原则：** 整合成熟开源项目，不重复开发现有能力；翻译质量优先于速度；模块解耦、可恢复、可验证。  
   
⸻  
   
## 一、项目目标  
构建一个本地运行的电子书自动处理工具。用户输入一本 PDF、EPUB、MOBI 或 AZW3 格式的电子书，系统自动识别文件类型、处理文本与排版、检测语言，并根据配置生成可用于 Kindle 等阅读器的电子书。  
**主要目标：**  
1. 自动识别 PDF、EPUB、MOBI、AZW3 输入。  
2. 对 PDF 自动判断是否需要 OCR，恢复可重排的正文结构。  
3. 对已有电子书尽可能保留章节、图片、目录、脚注和原始样式。  
4. 自动检测原书主要语言。  
5. 对非中文书籍使用本地 LLM 翻译成简体中文。  
6. 支持中文翻译版和原文/中文逐段对照版。  
7. 使用本地模型进行翻译审校及自动质量检查。  
8. 输出 EPUB，并可进一步转换为 AZW3。  
9. 支持断点续传、失败重试、缓存和任务日志。  
10. 所有处理默认在本地完成，无需云端 API。  
**不追求：** 最高处理速度、大规模并行翻译、商业化部署或复杂多用户系统。  
## 二、系统总体架构  
```
                    INPUT
       PDF / EPUB / MOBI / AZW3
                       |
                File Inspector
                       |
          +------------+------------+
          |            |            |
         PDF          EPUB       MOBI/AZW3
          |            |            |
   PDF Extractor       |         Calibre
   OCR + Layout        |            |
          |            |            |
          +------------+------------+
                       |
              Normalized EPUB
                       |
              Language Detector
                       |
         +-------------+-------------+
         |                           |
      Chinese                    Non-Chinese
         |                           |
         |                    Book Analyzer
         |                           |
         |                    LLM Translator
         |                           |
         |                    LLM Reviewer
         |                           |
         |                    Translation QA
         |                           |
         +-------------+-------------+
                       |
                 EPUB Builder
                       |
                EPUB Validation
                       |
                   Calibre
                       |
                EPUB / AZW3
```
系统采用 **Pipeline + Adapter** 架构。不同的第三方工具通过独立适配器接入，避免把整个项目与某个开源工具强绑定。  
## 三、技术栈与现有开源组件  

| 功能                | 优先候选                              | 使用方式              |
| ----------------- | --------------------------------- | ----------------- |
| PDF 文档解析、OCR、版面识别 | Marker                            | CLI / Python      |
| 电子书格式转换           | Calibre                           | ebook-convert CLI |
| EPUB 解析及重建        | EbookLib / 现有翻译项目                 | Python            |
| 双语 EPUB 翻译与生成     | BabelEbook / Bilingual Book Maker | CLI / Adapter     |
| 本地模型服务            | Ollama                            | HTTP API          |
| 语言检测              | fastText 或其他轻量检测库                 | Python            |
| 文本与译文审校           | Ollama LLM                        | 独立任务              |
| EPUB 格式验证         | EPUBCheck                         | CLI               |
| 任务调度与状态管理         | Python                            | SQLite / JSON     |
| 操作界面              | 首版 CLI                            | macOS Terminal    |
  
上述工具是候选方案而不是不可变依赖。Codex 开始实施前，应检查各项目最新的许可证、安装要求、支持格式、API/CLI 能力和实际输出。  
**集成规则：**  
* 优先调用现有软件的公开 API 或 CLI。  
* 不直接复制第三方项目的大量源码。  
* 如果某项目无法稳定集成，可以替换适配器。  
* 不需要在第一版中同时接入两个双语翻译引擎；先选择一个实现完整闭环。  
* 不假设 Marker 的 Markdown 输出能够无损还原任意 PDF；必须处理结构和图片。  
* 不绕过 DRM；只处理用户有权使用的、可读取的输入文件。  
## 四、输入处理  
**4.1 PDF**  
自动识别两种主要情况：  
**数字原生 PDF：** 优先提取已有文字层，进行版面分析与结构恢复。  
**扫描 PDF：** 将页面图像交给 OCR 与版面识别组件，恢复正文、标题、图片、表格和脚注。  
混合型 PDF 允许逐页决定是否 OCR，而不是仅对整份文档做一次二选一判断。  
主要处理事项：  
* 去除重复页眉、页脚和页码。  
* 恢复跨行段落，处理断词和错误换行。  
* 识别章节标题及标题层级。  
* 保留插图和必要的表格。  
* 尽可能恢复脚注与引用。  
* 标记低置信度或结构异常的页面。  
处理结果转换为标准化 EPUB，作为后续翻译引擎的输入。  
对无法可靠恢复的复杂公式、图文布局和表格，不允许静默删除，应保留原始图片或标记待检查。  
**4.2 EPUB**  
优先保留原始 XHTML、CSS、图片、目录和章节结构。  
不应为了翻译而先将整本 EPUB 转换成 TXT 或纯 Markdown，避免损失语义结构和排版信息。  
**4.3 MOBI / AZW3**  
通过 Calibre 转换为 EPUB。  
对有 DRM、格式损坏或转换失败的文件，返回明确错误，不尝试破解 DRM。  
## 五、语言检测与处理策略  
自动检测原书主要语言，默认目标语言为简体中文。  

| 原书语言 | 默认行为          |
| ---- | ------------- |
| 简体中文 | 仅格式处理         |
| 繁体中文 | 默认保留原文        |
| 英语   | 翻译为简体中文       |
| 德语   | 翻译为简体中文       |
| 其他语言 | 若检测与模型支持，允许翻译 |
| 无法确定 | 提示手动指定语言      |
  
应支持命令行覆盖自动检测结果。  
支持以下输出模式：  
* original：只进行格式转换，不翻译。  
* translated：仅生成目标语言译文。  
* bilingual：保留原文，并在每个对应段落后插入译文。  
默认模式为 bilingual，但用户可以覆盖。  
## 六、翻译引擎  
翻译引擎通过独立接口调用 Ollama，不与具体模型绑定。  
初始模型配置可以使用 TranslateGemma 12B 或其他本地模型。模型最终选择不属于 V1 的验收前提。  
翻译时应考虑：  
1. 以自然段或小段落组为基本翻译单位。  
2. 保留原文和译文之间的稳定 ID 映射。  
3. 为翻译任务提供必要的相邻上下文。  
4. 保留章节标题、强调、引用和必要的行内标记。  
5. 对专有名词和核心术语采用统一术语表。  
6. 不允许翻译模型擅自删减、总结或添加内容。  
7. 失败的段落可独立重试，而无需重新翻译整章。  
8. 翻译结果和中间状态持久化保存。  
建议采用章节级任务队列，以及段落级翻译缓存。  
缓存键应包含原文内容、源语言、目标语言、模型 ID、Prompt 版本、术语表版本及关键生成参数，防止模型切换后误用旧缓存。  
## 七、上下文管理  
为了避免整本书不断占用模型上下文窗口，采用分层上下文：  
* **全书级：** 书名、作者、体裁、写作背景、术语表、人物表。  
* **章节级：** 当前章节概要、人物与术语变化。  
* **局部级：** 当前翻译段落及前后相邻段落。  
章节摘要及术语表可以通过独立分析阶段生成。  
首版不要求复杂 Agent 框架、向量数据库或 RAG 系统。  
上下文应该由代码明确组装，而不是依赖一个无限增长的模型对话历史。  
## 八、翻译审校与质量检查  
将审校拆分为两层。  
**确定性检查：**  
* 原文段落是否全部得到对应输出。  
* 译文是否为空。  
* 段落 ID 是否重复或缺失。  
* 数字、年份、单位是否存在可疑变化。  
* 章节和目录是否缺失。  
* 双语段落顺序是否正确。  
* 图片、脚注和重要链接是否丢失。  
**LLM 语义审校：**  
* 是否存在漏译或增译。  
* 是否存在明显误译或否定关系颠倒。  
* 术语是否正确、一致。  
* 是否破坏原作者的观点和语气。  
* 中文是否通顺、有明显翻译腔。  
审校模型必须同时看到原文及译文。  
优先让模型返回结构化修改建议，而不是无条件重写全文。  
所有修订需要关联原段落、原因和版本记录，以便排查质量问题。  
V1 允许审校是可选阶段，但必须提供可用的审校接口与基本实现。  
## 九、双语 EPUB 输出  
默认采用适合 Kindle Oasis 7 英寸屏幕的**上下逐段对照**排版，而不是左右两栏。  
```
Original paragraph 1

中文译文第一段

Original paragraph 2

中文译文第二段
```
要求：  
* 段落对应关系明确。  
* 不重复插入翻译文本。  
* 不破坏章节顺序。  
* 尽量继承原书字体、缩进及正文样式。  
* 使用简洁的原文/译文区分方式。  
* 保留目录、图片和可恢复的脚注。  
* 对代码、公式、链接、书目等特殊内容使用独立处理规则。  
* 不依赖外部 CSS 或远程字体资源。  
* EPUB 可通过 EPUBCheck 验证。  
当原书有复杂嵌套标签时，不允许简单地用字符串替换整个 XHTML 文件。  
## 十、任务恢复与错误处理  
因为翻译一本几百页的书可能耗时较长，任务必须支持恢复。  
每本书建立独立工作目录：  
```
workspace/
  book-id/
    source/
    extracted/
    normalized/
    metadata/
    translations/
    reviews/
    output/
    logs/
    state.json
```
要求：  
* 每阶段完成后保存结果。  
* 翻译过程中增量持久化。  
* 支持失败后从上次已完成任务继续。  
* 不因某一段翻译失败而丢失其他结果。  
* 支持手动重试失败段落。  
* 日志明确记录失败的阶段和位置。  
* 能重新执行某个阶段，并正确使后续依赖结果失效。  
## 十一、命令行接口  
首版提供 CLI，不需要复杂 Web UI。  
示例命令为目标接口设计，并不表示已有可执行程序：  
```
bookflow convert book.pdf
bookflow convert book.epub \
  --target zh-CN \
  --mode bilingual \
  --output epub,azw3
bookflow convert book.pdf \
  --source de \
  --target zh-CN \
  --model trans-gemma \
  --review-model qwen-review \
  --mode bilingual
bookflow resume <job-id>
```
还应支持：  
* 查看任务状态。  
* 查看失败段落。  
* 手动指定语言。  
* 开启或关闭 OCR。  
* 开启或关闭审校。  
* 选择输出目录。  
* 指定不同阶段所使用的模型。  
参数应通过统一配置文件管理，例如 config.yaml。  
## 十二、建议配置结构  
```
runtime:
  platform: macos
  ollama_url: http://localhost:11434

models:
  translation: translategemma:12b
  review: qwen3:14b

processing:
  target_language: zh-CN
  output_mode: bilingual
  keep_intermediate_files: true
  resume_enabled: true

pdf:
  engine: marker
  ocr_mode: auto

translation:
  context_mode: chapter
  glossary_enabled: true
  chunk_size: 1200
  concurrency: 1

review:
  enabled: true
  max_revision_rounds: 1

output:
  formats:
    - epub
    - azw3
  validate_epub: true
```
模型名称、参数规模和批次大小均为初始占位配置，需要按实际 Ollama 模型标签、内存占用以及工具兼容性调整。  
## 十三、开发阶段  
**Phase 1 — 工具链集成**  
完成项目框架，接入 Calibre、Marker、EPUB 解析库及 Ollama。  
实现从不同输入文件得到可继续处理的电子书格式。  
交付：  
* CLI 框架。  
* 文件类型识别。  
* PDF 处理适配器。  
* Calibre 转换适配器。  
* 标准化 EPUB 输出。  
**Phase 2 — 本地翻译闭环**  
接入一个现成的双语 EPUB 翻译组件。  
实现：  
* 语言检测。  
* 本地模型调用。  
* 中英、中德双语生成。  
* 翻译缓存。  
* EPUB/AZW3 最终输出。  
这一阶段完成后，系统已经具备实用价值。  
**Phase 3 — 翻译质量与可靠性**  
增加：  
* 术语表与章节上下文。  
* 独立审校接口。  
* 确定性质量检查。  
* 错误重试及断点恢复。  
* 阶段日志和异常报告。  
**Phase 4 — 体验完善**  
根据实际使用结果优化：  
* 批量任务。  
* 简单 Web UI。  
* 单页/单段人工修订。  
* 翻译质量测试与模型选择。  
* OCR/排版问题的可视化审查。  
Phase 4 不属于第一版 MVP 的必要范围。  
## 十四、V1 验收条件  
至少准备以下五类测试文件：  

| 测试样本              | 预期结果           |
| ----------------- | -------------- |
| 原生英文 EPUB         | 生成有效的中英双语 EPUB |
| 原生德文 EPUB         | 生成有效的德中双语 EPUB |
| 数字原生英文 PDF        | 提取文本并生成双语 EPUB |
| 扫描英文 PDF          | OCR、结构恢复、翻译并输出 |
| 无 DRM 的 MOBI/AZW3 | 转为 EPUB 后完成翻译  |
  
此外，需要验证：  
1. 一份中文 EPUB 在默认配置下不会被错误翻译。  
2. 翻译任务被中断后能恢复，不重复处理已完成段落。  
3. 切换模型只需修改配置，无需修改核心流程。  
4. 输出 EPUB 可以通过结构验证。  
5. 输出 AZW3 可以被 Calibre 识别。  
6. 双语书的章节顺序、图片、主要段落不丢失。  
7. 输入文件保持不变。  
8. 缺少外部工具、模型不可用、文件损坏等情况有明确错误提示。  
9. 至少选取一份较短的电子书完成端到端实际阅读验证。  
注意：EPUBCheck 通过不代表排版或译文完全正确。扫描 PDF 的自动结构恢复也不可能保证所有书籍达到零错误。应报告未解决的质量问题，而不是静默认为任务成功。  
## 十五、暂不实施的功能  
第一版不做：  
* 模型自动排名与最优模型选择。  
* 多模型投票、复杂 Agent 辩论。  
* 商业级排版与人工翻译平台。  
* 云端部署和多用户管理。  
* 自动抓取或下载书籍。  
* DRM 破解。  
* Kindle 固件修改。  
* PDF 原始复杂版面的像素级复原。  
* 全自动保证零错字、零误译。  
* 复杂的前端界面。  
## 十六、开发实施原则  
**尽量少写代码，只开发现有工具之间必需的编排、接口、状态管理和质量控制。**  
避免为了统一而重复实现成熟项目的内部功能。  
在最终确定依赖前，验证开源项目的实际能力。若某个现成项目不能提供稳定的 CLI/API、不能保留必要的排版结构，或其许可证不兼容，则通过适配器替换。  
优先交付一个能真正处理完整书籍、可恢复、可检查的最小系统，而不是堆叠大量尚未验证的功能。  
   
⸻  
   
**最终交付目标：** 在 Mac mini M4 24GB 上，用户通过一条命令，将可读取的 PDF、EPUB、MOBI、AZW3 电子书处理成结构正确、可在 Kindle Oasis 阅读的简体中文或双语 EPUB/AZW3 电子书，翻译和审校全过程能够使用本地 Ollama 模型完成。
